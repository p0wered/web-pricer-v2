# WebPricer v2 — решения и план разработки

> Документ зафиксирован по итогам обсуждения 29.09.2026; в тот же день дополнен ответами на открытые вопросы.
> Источник правды по функциональности — старый проект `../web-pricer` (Laravel 11 + Inertia + React)
> и файл `Pricer.xlsm`. Старый проект используется только как справочник поведения и ошибок; код не переносится.

---

## 1. Цель и рамки

- **Реворк с нуля**: новый проект с тем же набором пользовательских функций, что и в старом.
- **Главные приоритеты**: скорость и качество поиска, UI.
- **Критерий скорости — относительный.** Абсолютных порогов («поиск < N мс») нет: итог зависит от сервера заказчика. Делаем всё, что ускоряет поиск и импорт, и доказываем результат сравнением со старой версией на одной машине и одних данных («было 500 мс — стало 50 мс»), см. §8.
- **Новых пользовательских функций не добавляем.** Внутреннюю логику (поиск, импорт, хранение) переделываем свободно.
- Мелкие улучшения существующего откладываем до достижения паритета (см. §10 «Бэклог»).

**Окружение заказчика:**
- Сервис доступен по **https://pricer.gate12a.com**. HTTPS обеспечивает инфраструктура заказчика; как именно она устроена, мы не знаем.
- Разворачивает **DevOps заказчика**: мы передаём архив с проектом и инструкцией в README, дальше они разворачивают сами. Значит, README должен быть самодостаточным, а запуск — не сложнее, чем у старой версии (`docker compose up -d --build`).
- Сервер и внешний порт — **как у старой версии (9091)**, чтобы настройки прокси заказчика не пришлось менять.
- Интерфейс рассчитан на десктоп; часовой пояс — Europe/Moscow.

## 2. Исходные данные: что внутри Excel

Файл `Pricer.xlsm` собирается VBA-макросом из прайсов поставщиков и лежит на DAV-сервере.

| Параметр | Значение |
|---|---|
| Размер | ~52 МБ zip, ~339 МБ XML внутри, ~1 млн уникальных строк в `sharedStrings` |
| Листов | 157 |
| Служебные (не импортируются) | `Request` (список отобранных позиций макроса), `Suppliers` (конфиг макроса: поставщики, email, маски файлов, ссылки) |
| Листы с `>` → **Стоп-лист** | 6 листов, ~45 тыс. строк: `>STOP` (66), `>Sklad` (~5 тыс.), `>PI` (~8,6 тыс.), `>Spam` (~16 тыс.), `>Denis` (~12,7 тыс.), `>Zavod` (~2,3 тыс.) |
| Остальные → **Детали** | 149 листов поставщиков, ~1,6 млн строк; крупнейшие: Ркомп 487 тыс., minidip 214 тыс., ЭРК 129 тыс. |

**Структура листа** (одинакова для всех листов данных):
- `A1` — «`<Поставщик> от ДД.ММ.ГГГГ`» (есть на всех листах), `C1:E1` — «Всего N строк.» (формула);
- строка 2 — шапка, генерируется макросом (Название / Дата(Год) / Кол-во / Цена / Описание) — смысла колонок не отражает;
- данные с 3-й строки: `A` Название, `B` Год, `C` Кол-во, `D` Цена, `E` Описание.

**Особенности данных** (важно для импорта и поиска):
- В стоп-листах колонка `B` значит разное: `STOP` — метка «!!! STOP !!», `PI` — поставщик, `Zavod` — срок поставки, в остальных — год. Могут появляться новые `>`-листы.
- Цены — часто строки: в Деталях ~198 тыс. нечисловых цен («По запосу» ~157 тыс., «звоните», «дог», «уточняйте», «99,99», «999-99», «180р»); в `PI` — «29 $», «190 Rs.»; у `EdTula` в колонке цены — артикул «D55501.1».
- Количество: ~47 тыс. нечисловых («>1000», «<10», «199шт»).
- Год: «бг», «83-93г», «2014,Элекон»; у части поставщиков год внутри названия — «(87г)», «(2002г.)».
- Мусорные символы: NBSP, BOM, zero-width space, переносы строк; ведущие/хвостовые пробелы.
- Латиница и кириллица вперемешку (~22 тыс. строк с токенами вида `2PМТ22КУЭ4Г3В1В`, `MПО`; лист `K52-2` назван с латинской K).
- Разные записи одного и того же: `К52-1В-50В-3.3мкф-10%`, `К52-1В 16В 220мкф 10%`, `к52-9в-50в-33мкФ-10% (2015г.)`, `К52-2 15в-400м 20%`.
- Кривые листы: у `tlt` съехали колонки, у `grom` всё записано одной строкой в названии, встречаются строки-заголовки групп («ФОНАРИ СИГНАЛЬНЫЕ»). Это проблемы конфига макроса — приложение импортирует как есть.

**Оригинальный поиск Excel** (VBA `UserForm1`, его копировал старый веб): минимум 3 символа, без учёта регистра, пробел → `*`, `,` и `.` → «любой символ»; все слова кроме последнего — по порядку, последнее — где угодно; кнопки Копировать/Вставить/Вырезать и принудительная русская раскладка — оттуда же.

**Замеры прототипа на реальных данных** (MacBook, одиночный поток; справочно, не как целевые значения):
- потоковый разбор всей книги (Python stdlib) — ~17 с; старый импорт грузил книгу целиком в память;
- поиск перебором по нормализованным названиям в Node (без индекса) — **7–25 мс** на запрос по 1,65 млн строк;
- полнота нормализованного поиска против старого:

| Запрос | Старый | Нормализованный |
|---|---:|---:|
| `K52-1 50в` (латинская K) | 0 | 1149 |
| `к52 33мкф` | 1124 | 1163 |
| `кт315` | 638 | 676 |
| `с2-33н 0.25 10к` | 207 | 255 |
| `мпо` | 3129 | 3349 |

## 3. Принятые решения

| Вопрос | Решение |
|---|---|
| Язык и фреймворк бэкенда | **Node.js 24 LTS + TypeScript + Fastify** |
| Хранилище | **SQLite** (один файл в volume): настройки, пароль, сессии, журнал импортов, снимок данных |
| Поиск | Собственный движок **в памяти процесса** + нормализация + ранжирование (§6.5) |
| Фронтенд | React 19 + TypeScript + Vite + Tailwind CSS 4 |
| Авторизация | **Общий пароль, как сейчас** |
| Автоимпорт | **По расписанию, как сейчас** (ежедневно / еженедельно / ежемесячно + время) + ручной запуск |
| Запуск поиска | **По Enter / кнопке «Поиск»**, как сейчас |
| Логика сопоставления | Нормализация + ранжирование, на усмотрение разработки ради скорости и качества |
| Колонка `B` стоп-листа | Нейтральная подпись **«Год / инфо»** для всех `>`-листов — работает с любыми новыми листами без настройки |
| Порядок групп стоп-листа | **По порядку листов в книге** (как у макроса Excel); новые листы встают на своё место автоматически. По имени особо обрабатывается только `>STOP` (красная подсветка) |
| Мелкие доработки | Отложены в бэклог до паритета |
| Новые функции (заявка поставщику, свежесть прайсов, фильтры/история, экспорт) | **Не делаем** |
| Структура репозитория | Монорепо на npm workspaces: `apps/server`, `apps/web`, `packages/shared` |
| Деплой | Один Docker-контейнер (API + собранный фронт) + volume для данных; передаётся DevOps заказчика архивом с README; внешний порт `9091`, как у старой версии |
| Сессия | 120 минут неактивности, как в старой версии |
| Критерий скорости | Относительный: сравнение со старой версией на одной машине и одних данных; абсолютных порогов нет |

## 4. Функциональный паритет (чек-лист приёмки)

**Вход / выход**
- [ ] Вход по одному общему паролю, сообщения об ошибках на русском.
- [ ] Ограничение попыток входа (5 попыток, затем блокировка с сообщением «повторите через N сек.»).
- [ ] Выход.

**Поиск**
- [ ] Строка поиска, запуск по Enter и кнопке «Поиск».
- [ ] Запрос отражается в URL (перезагрузка / «назад» работают).
- [ ] Переключатель **EN→RU** (конвертирует вводимый/вставляемый текст по раскладке), состояние сохраняется в `localStorage`.
- [ ] Кнопки **Вставить / Копировать / Вырезать**.
- [ ] Две таблицы с количеством найденного: **Стоп-лист** (строки из `>`-листов) и **Детали** (остальные листы).
- [ ] Стоп-лист: Название, Год / инфо, Кол-во, Цена, Поставщик (имя листа без `>`), Описание; строки `>STOP` — красным; группы по порядку листов в книге.
- [ ] Детали: Название, Год, Кол-во, Цена, Поставщик (текст `A1` листа, напр. «РадиоКомплект от 21.09.2026»).
- [ ] Цвет строки по поставщику.
- [ ] Сортировка Деталей по цене: нет → по возрастанию → по убыванию → нет; пустые цены в конце.
- [ ] Прокручиваемые таблицы со всеми результатами (без постраничной навигации).
- [ ] Пустые состояния («Нет данных для отображения»).

**Настройки**
- [ ] Смена пароля: текущий / новый / подтверждение, минимум 8 символов.
- [ ] Настройки импорта: URL файла, логин, пароль DAV, частота (ежедневно / еженедельно / ежемесячно), день, время `ЧЧ:ММ` с маской ввода.
- [ ] Ручной импорт: кнопка, индикатор «Импорт выполняется…», итог с понятными ошибками (401 → «Ошибка авторизации. Проверьте логин и пароль.», недоступный хост → «Не удалось подключиться по указанному URL», прочее → «Ошибка при импорте»).
- [ ] Возврат к поиску.

**Импорт**
- [ ] Скачивание файла по URL с Basic Auth.
- [ ] Листы `Request` и `Suppliers` пропускаются; первые 2 строки листа пропускаются; строки с пустым названием пропускаются.
- [ ] `>`-листы → стоп-лист, остальные → детали; полная замена данных при каждом импорте.
- [ ] Автозапуск по расписанию из настроек (Europe/Moscow).

**Администрирование (аналоги artisan-команд)**
- [ ] CLI: запустить импорт, сменить пароль, показать время следующего запланированного импорта.

## 5. Что исправляем относительно старого проекта

| Проблема старой версии | Как решаем в v2 |
|---|---|
| `LIKE '%…%'` без индексов по 1,6 млн строк, `ORDER BY CASE …`, без лимита; вся выдача сериализуется во фронт дважды (`data` + `allData`) | Движок в памяти (§6.5); сервер отдаёт выдачу порциями, таблицы подгружают строки при прокрутке |
| Широкие запросы (`к52`, `к50`, `с2-33`, `2рм`…) всегда падают с HTTP 500: выдача целиком пишется в кэш-таблицу MySQL и не влезает в колонку (найдено на замере этапа 0, см. `docs/benchmarks.md`) | Выдача не кэшируется целиком: в LRU-кэше только упорядоченные id, строки отдаются порциями |
| Нет нормализации: `K52` (лат.) ≠ `К52`, «33 мкФ» ≠ «33мкф»; числа как подстроки («15пф» находит «115пф») | Нормализация + правило границы числа (§6.5) |
| Импорт грузит всю книгу в память (`memory_limit = -1`), минуты работы | Потоковый разбор XLSX в отдельном потоке (`worker_threads`) |
| `TRUNCATE` до загрузки: во время импорта поиск пустой, при ошибке база пустая/частичная | Загрузка в staging-таблицы и атомарная подмена; старые данные и индекс работают до конца импорта |
| Ручной импорт — синхронный HTTP-запрос до 50 минут; нет защиты от параллельного запуска с планировщиком; код импорта скопирован в двух местах | Импорт — фоновая задача с одним общим кодом; блокировка «один импорт одновременно»; фронт опрашивает статус |
| Нечисловые цены → `NULL` (потеряно ~198 тыс. цен, из них ~17 тыс. настоящих вида «99,99», «180р»); количества «>1000» → `NULL` | Храним исходный текст + распознанное число отдельно; показываем исходный текст, сортируем по числу |
| `substr(…, 0, 255)` режет UTF-8 посреди символа | Текст хранится целиком, обрезка только визуальная |
| Подпись «Год» в стоп-листе, хотя в `PI` это поставщик, в `Zavod` — срок; устаревший приоритет групп `["STOP","RK","PI"]` | Подпись «Год / инфо»; порядок групп — порядок листов в книге |
| Пароль DAV хранится открытым текстом и показывается в форме (`type="text"`) | Шифрование на диске (AES-256-GCM, ключ из `APP_SECRET`); API никогда не возвращает пароль, поле только для записи |
| Пароль входа по умолчанию `12341234`; пароль БД закоммичен в `docker-compose.yml` | Начальный пароль задаётся через env при первом старте; секреты только в `.env` (в репозитории — `.env.example` без значений) |
| Для еженедельного импорта день валидируется как 1–31 | Для недели — выбор Пн…Вс; для месяца 1–31; если в месяце меньше дней — запуск в последний день месяца |
| Цвет поставщика — сумма кодов символов по модулю 13 (много коллизий) | Стабильный хэш (FNV-1a) по палитре мягких цветов |
| Фиксированные ширины панелей, обрезка текста без подсказки | Аккуратная сетка, sticky-заголовки, полный текст во всплывающей подсказке |

## 6. Архитектура

### 6.1. Структура репозитория

```
web-pricer-v2/
├─ apps/
│  ├─ server/                 # Fastify: API, импорт, поисковый движок, планировщик, CLI
│  │  └─ src/
│  │     ├─ api/              # маршруты: auth, search, settings, import, health
│  │     ├─ auth/             # пароль (scrypt), сессии, rate limit
│  │     ├─ db/               # подключение SQLite, миграции, запросы
│  │     ├─ import/           # DAV-клиент, потоковый XLSX-ридер, разбор строк, воркер
│  │     ├─ search/           # индекс, сопоставление, ранжирование, кэш выдачи
│  │     ├─ scheduler/        # расписание импорта
│  │     └─ cli.ts            # import | password | schedule
│  └─ web/                    # React SPA
│     └─ src/{pages,components,api,lib}
├─ packages/
│  └─ shared/                 # zod-схемы и типы API, normalize(), конвертер EN→RU
├─ Dockerfile
├─ docker-compose.yml
├─ .env.example
└─ PLAN.md
```

### 6.2. Бэкенд

- Node.js 24 LTS, TypeScript (strict), ESM. Сервер запускается **прямо из TS-исходников** (нативный type stripping Node) и в разработке (`--watch`), и в проде — отдельного шага сборки сервера нет; `tsc` используется только для проверки типов. Поэтому в коде — только «стираемый» синтаксис (`erasableSyntaxOnly`: без `enum`, `namespace`, parameter properties) и импорты с расширением `.ts`. Локально достаточно Node ≥ 22.18, в Docker — Node 24.
- TypeScript 6.0 (не 7.x): typescript-eslint пока поддерживает TS только до 6.0.
- Fastify 5: `@fastify/static` (раздача SPA), `@fastify/cookie`, `@fastify/rate-limit`; валидация входа/выхода — zod-схемы из `packages/shared`.
- SQLite через `better-sqlite3` (WAL). Альтернатива — встроенный `node:sqlite`, если к началу работ он стабилен. Миграции — простые SQL-файлы, применяются при старте.
- Логи — pino (встроен в Fastify) в stdout.

### 6.3. Модель данных (SQLite)

```
settings      (id=1, dav_url, dav_username, dav_password_enc,
               schedule_frequency: daily|weekly|monthly, schedule_day, schedule_time, updated_at)
auth          (id=1, password_hash /* scrypt */, updated_at)
sessions      (id, created_at, last_seen_at, expires_at)
import_runs   (id, trigger: schedule|manual|cli, status: running|success|failed,
               started_at, finished_at, rows_main, rows_special, error)
sheets        (id, name /* как в книге, с '>' */, kind: main|special, title /* текст A1 */,
               supplier_label, sort_order /* позиция в книге */, row_count)
items         (id, sheet_id, name, year_text, qty_text, qty_num, price_text, price_num, description)
```

- `supplier_label`: для деталей — текст `A1` (как в старом), для стоп-листа — имя листа без `>`.
- `price_num` / `qty_num` распознаются из текста: «99,99» → 99.99, «999-99» → 999.99, «180р» → 180, «1 600» → 1600, «>1000» → 1000; «По запосу», «звоните», «дог», «D55501.1» → `NULL`. Валюта в `PI` («29 $», «190 Rs.») → число не выделяется (разные валюты несравнимы), показывается исходный текст.
- Импорт пишет в `sheets_staging` / `items_staging`, затем одной транзакцией подменяет таблицы.

### 6.4. Импорт

1. **Блокировка**: если есть `import_runs.status = running`, новый запуск отклоняется (ручной получает «Импорт уже выполняется»).
2. **Скачивание**: `fetch` (undici) с Basic Auth, таймауты, поток во временный файл в `data/tmp` (zip требует произвольного доступа — центральный каталог в конце файла).
3. **Разбор** в `worker_thread`: zip → `sharedStrings.xml` в память (~1 млн строк) → листы потоково (SAX), без построения книги в памяти. Реализация — собственный минимальный ридер (`yauzl` + SAX-парсер); запасной вариант — потоковый `ExcelJS.WorkbookReader`. Выбор — по замеру на этапе 1.
4. **Разбор строк**: пропуск `Request` / `Suppliers` (список в конфиге) и первых двух строк; очистка текста (NBSP → пробел, удаление BOM / zero-width / управляющих символов, trim); распознавание `price_num` / `qty_num`.
5. **Запись** пачками в staging-таблицы в одной транзакции → атомарная подмена.
6. **Индекс** строится в воркере, передаётся в основной поток (transferable `ArrayBuffer`) и подменяется одной операцией; кэш выдачи сбрасывается (ключ содержит версию данных).
7. **Итог** пишется в `import_runs`; временный файл удаляется в любом исходе. При ошибке старые данные и индекс остаются рабочими.

Время импорта и пиковую память сравниваем со старой версией (§8), абсолютных порогов нет.

### 6.5. Поисковый движок

**Нормализация** (`packages/shared`, чистые функции, покрыты тестами на реальных строках из файла), одинаково для данных и запроса:
1. Unicode NFKC; удаление BOM / zero-width / мягких переносов; NBSP → пробел.
2. Нижний регистр, `ё` → `е`.
3. Гомоглифы латиница → кириллица: `a b c e h k m o p t x y` → `а в с е н к м о р т х у`. Применяется к обеим сторонам, поэтому латинские названия (`BZX79`, `SAMSUNG`) продолжают находиться.
4. Десятичная запятая между цифрами → точка (`0,25` → `0.25`).
5. Единицы после числа: `мкф / µf / μf / uf` → `мкф`; `пф / pf` → `пф`; `нф / nf` → `нф`; `ком / kohm` → `к`; `мом / mohm` → `м`; `v` → `в`. Таблица правил — в одном месте, расширяется тестами.
6. Разделители (`- _ / ( ) " « » , ; :` и пробелы) → единый разделитель; точка, не стоящая между цифрами, — тоже разделитель.
7. Нормализатор хранит карту позиций «нормализованный → исходный текст», чтобы позже добавить подсветку без переделки.

**Сопоставление:**
- Запрос делится на слова по пробелам; каждое слово нормализуется и «сжимается» (без разделителей): `к52-1б` → `к521б`.
- Позиция подходит, если **каждое** слово найдено в названии (порядок любой); между символами слова в названии допускается разделитель (`к521б` ≈ `К52-1Б`, `к52 1б`).
- **Граница числа**: если слово начинается с цифры, перед совпадением не должно быть цифры или десятичной точки (`15пф` ≠ `115пФ`, `0.15пФ`). Если слово заканчивается на единицу (`6.8к`), после совпадения не должно быть буквы (`6.8к` ≠ `6.8кв`).
- Поиск идёт только по названию (как в старом).

**Ранжирование** (по убыванию веса):
1. Первое слово запроса совпадает с началом названия (семейство детали, напр. «к52» в «к52 15пф 33ом»); затем — с началом любого токена.
2. Слова идут в том же порядке, что в запросе (семантика Excel-поиска).
3. Точное окончание числовых слов (`кт315` → `КТ315А` выше, чем `КТ3151Б9`; `33мкф` без продолжения).
4. Более короткое название (меньше лишнего).
5. Название по алфавиту.
При сортировке по цене релевантность — вторичный ключ.

**Выдача:**
- Стоп-лист: группы по `sheets.sort_order`, внутри группы — по релевантности (или цене).
- Детали: по релевантности или по цене.
- Сервер держит в LRU-кэше упорядоченный список id по ключу (версия данных, нормализованный запрос, список, сортировка) и отдаёт порции по 200 строк; строки для порции читаются из SQLite по id.

**Реализация (поэтапно):**
- Шаг 1 — корректность: перебор по «сжатым» названиям, закодированным в однобайтовую строку, + точная проверка найденных кандидатов. Это эталон для тестов качества.
- Шаг 2 — скорость: триграммный инвертированный индекс (`Uint32Array` со списками id) для отбора кандидатов. Оставляем вариант, который быстрее на бенчмарке, при одинаковой выдаче на регрессионном наборе.

**Прочие меры для скорости по всей цепочке:**
- сервер отдаёт порции по 200 строк, а не всю выдачу; сжатие ответов (`@fastify/compress`);
- новый запрос отменяет предыдущий (`AbortController`);
- виртуализация таблиц на фронте — в DOM только видимые строки;
- индекс строится при старте и после импорта, запросы никогда не ждут построения;
- LRU-кэш выдачи для прокрутки и смены сортировки.

Скорость оцениваем относительно старой версии (§8).

### 6.6. API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/login` | `{ password }` → cookie сессии; rate limit 5/мин на IP |
| POST | `/api/auth/logout` | Выход |
| GET | `/api/auth/me` | Проверка сессии |
| GET | `/api/search?q&list=main\|special&sort=relevance\|price_asc\|price_desc&offset&limit` | `{ total, items[], dataVersion }` |
| GET | `/api/settings` | Настройки импорта (без пароля DAV: только `davPasswordSet: boolean`) |
| PUT | `/api/settings` | Сохранение настроек, перепланирование без перезапуска |
| POST | `/api/settings/password` | `{ current, password, confirmation }` |
| POST | `/api/import` | Запуск ручного импорта → `202 { runId }` или `409`, если импорт уже идёт |
| GET | `/api/import/:id` | Статус запуска (для индикатора в настройках) |
| GET | `/api/health` | Проверка живости для Docker |

Все схемы запросов и ответов — в `packages/shared` (zod), типы выводятся из них для сервера и клиента.

### 6.7. Планировщик

- `croner` внутри процесса сервера, часовой пояс Europe/Moscow.
- Выражение строится из настроек: daily `HH:MM`; weekly — день недели (Пн…Вс) + `HH:MM`; monthly — число 1–31 + `HH:MM` (если в месяце меньше дней — последний день).
- Изменение настроек применяется сразу; запуск по расписанию проходит через ту же блокировку, что и ручной.
- CLI `schedule` показывает время следующего запуска.

### 6.8. Безопасность

- Пароль входа — `scrypt` (`node:crypto`), минимум 8 символов. Начальный пароль берётся из `APP_INITIAL_PASSWORD` при первом старте (если пароль в БД не задан и переменной нет — сервер не стартует с понятным сообщением); сменить можно в настройках или через CLI.
- Сессия — случайный id в cookie `HttpOnly; SameSite=Lax`; время жизни — 120 минут неактивности, как в старом (настраивается env).
- Пароль DAV шифруется ключом из `APP_SECRET`; в API только на запись; в форме — `type="password"` с пометкой «задан».
- API принимает только JSON (защита от CSRF вместе с `SameSite`).
- **Работа за HTTPS-прокси заказчика** (устройство прокси нам неизвестно, поэтому всё настраивается через env с безопасными значениями по умолчанию):
  - `TRUST_PROXY=true` — брать IP клиента из `X-Forwarded-For`. Иначе все пользователи будут выглядеть как один IP прокси, и 5 неудачных попыток входа одного человека заблокируют вход всем;
  - `COOKIE_SECURE=auto` — флаг `Secure` ставится, если прокси передаёт `X-Forwarded-Proto: https`; можно принудительно включить (`true`) или выключить (`false`);
  - никаких абсолютных URL и привязки к домену в коде — приложение работает на любом хосте и порту.

### 6.9. Фронтенд

- React 19, TypeScript, Vite, Tailwind CSS 4, React Router (страницы `/login`, `/search`, `/settings`), TanStack Query (запросы), TanStack Virtual (виртуализация таблиц). Собственные лёгкие компоненты без тяжёлого UI-кита.
- **Поиск**:
  - верхняя панель: поле, «Поиск», EN→RU, Вставить / Копировать / Вырезать, Настройки, Выйти;
  - ниже две панели — Стоп-лист и Детали с количеством найденного; sticky-заголовки, виртуализированные строки, подгрузка порций при прокрутке;
  - пустой стоп-лист сворачивается в узкую колонку;
  - длинный текст обрезается с полным значением во всплывающей подсказке;
  - цена — числом в формате ru-RU, если распознана, иначе исходный текст;
  - автофокус на поле; состояния загрузки и ошибок.
- **Настройки** — три блока, как в старом: смена пароля, ручной импорт (со статусом через опрос `/api/import/:id`), настройки импорта.
- **Вход** — одно поле пароля.
- Визуально — светлая, плотная, «рабочая» таблица, рассчитанная на длительную работу.

### 6.10. Развёртывание

**Что передаём:** архив с проектом (без `node_modules`, `data`, `.env`) и README; DevOps заказчика разворачивает сам, так же как старую версию.

- Multi-stage `Dockerfile`: сборка `web` и `server` → рантайм `node:24-slim`; сервер раздаёт API (`/api`) и статику SPA. Всё собирается внутри Docker — на сервере не нужны ни Node, ни npm.
- `docker-compose.yml`:
  - один сервис, порт `9091:3000` — тот же внешний порт, что у старого nginx, поэтому прокси заказчика на https://pricer.gate12a.com менять не нужно;
  - `container_name: webpricer2` — не пересекается с контейнерами старой версии (`app`, `webpricer-nginx`, `webpricer_db`, `laravel_scheduler`);
  - volume `./data:/app/data` (SQLite + временные файлы);
  - env: `TZ=Europe/Moscow`, `APP_SECRET`, `APP_INITIAL_PASSWORD`, `TRUST_PROXY`, `COOKIE_SECURE`;
  - healthcheck на `/api/health`, `restart: unless-stopped`;
  - работает и с `docker compose`, и со старым `docker-compose` (в старом README использовался второй вариант).
- **Переход со старой версии:**
  - старая версия останавливается (`docker-compose down` в её папке; данные MySQL остаются в её volume), новая запускается на том же порту;
  - данные не мигрируются — заново импортируются из DAV; настройки DAV один раз вводятся в новом интерфейсе;
  - откат: остановить новую версию и снова поднять старую.
- **README на русском**, рассчитан на человека, который видит проект впервые:
  - требования (Docker + Compose, доступ контейнера к DAV-серверу);
  - заполнение `.env` (как сгенерировать `APP_SECRET`, начальный пароль);
  - запуск и обновление;
  - первый импорт (кнопка в настройках или CLI);
  - смена пароля и прочие команды CLI (аналог разделов старого README);
  - где лежат данные;
  - переход со старой версии и откат;
  - заметка о прокси (`TRUST_PROXY`, `COOKIE_SECURE`).

## 9. Риски и заметки

- **Инфраструктура заказчика нам неизвестна.** Мы не видим сервер, прокси и процесс развёртывания. Поэтому:
  - всё, что зависит от окружения (прокси, cookie, порт), настраивается через env;
  - README проверяется развёртыванием с нуля на чистой машине;
  - сценарий отката на старую версию описан заранее.
- **Кнопки буфера обмена** (`navigator.clipboard`) требуют HTTPS — сервис открывается по HTTPS, так что работают. Локально (`localhost`) тоже работают.
- **Качество данных** (съехавшие колонки `tlt`, артикул в цене у `EdTula`, строки-заголовки групп) исправляется в конфиге макроса на листе `Suppliers`, а не в приложении.
- **Память**: снимок данных в SQLite + индекс в памяти; во время импорта кратковременно живут два индекса. Пиковую память замеряем и указываем в README как требование к серверу.
